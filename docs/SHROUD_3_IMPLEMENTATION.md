# Adaptive Shroud 3 Linux CLI/TUN and Lab API

Status: **experimental implementation; not release validated**.

Shroud 3 is a distinct, opt-in envelope for adaptive morphology over an already
authenticated standards-QUIC connection. It reuses the bounded caller-driven
workload policy introduced with Shroud 2, while changing the wire marker to
`S3` version `1`. Shroud 2 remains unchanged and remains the default when no
morphology API is selected.

## Rust API

Create one `AdaptiveShroud3` per direction or session and supply the same
session-relative monotonic clock and queue-age observations used by the
application scheduler:

```rust,ignore
let mut morphology = AdaptiveShroud3::new(WorkloadConfig::default())?;
connection
    .send_shroud3_adaptive_datagram_paced(
        &mut morphology,
        payload,
        WorkloadObservation {
            observed_at: session_elapsed,
            queue_age: enqueue_age,
        },
        &pacer,
        enqueued_at,
        cancel,
    )
    .await?;
let payload = peer_connection.recv_shroud3_datagram().await?;
```

The sender uses OS-seeded randomness by default. `from_seed` is for deterministic
tests and reproducible lab work; it is not suitable for emitting production
padding. The API does not infer application identity, inspect payload content,
or create a hidden observation clock. Callers must configure both peers to use
the Shroud 3 decoder. A Shroud 2 frame, unknown version, invalid length, or
invalid workload observation is rejected. There is no implicit format downgrade.

## CLI and saved session configuration

The Linux standards-QUIC native-TUN bridge has an explicit Shroud 3 opt-in.
Select it on both peers with `--shroud3-adaptive`:

```text
shph host --transport quic-standard --shroud3-adaptive
shph join --ticket-file host.ticket --quic-cert server.der --shroud3-adaptive
```

An existing connect/listen session can use `shph up --shroud3-adaptive`, or
persist the choice with:

```toml
[session]
shroud3_adaptive = true
```

The flag and setting are not carried in the join ticket or negotiated by the
handshake. Both peers must be configured consistently. A mode mismatch is
handled by strict envelope/IP validation and the configured invalid-datagram
limit; SHPH does not fall back to another envelope. The CLI rejects TCP, the
legacy QUIC shim, SNAP plans, Phantom One, one-shot sessions, `--no-tun`, and
non-Linux hosts for this integration. It also requires an actual native TUN at
startup, even if `--no-tun` was omitted.

## Wire and support boundaries

- The fixed seven-byte header contains `S3`, version `1`, payload length, and
  declared datagram length. Tail bytes are padding generated by the morphology
  engine.
- QUIC authenticates the full datagram before this envelope is interpreted.
- `shph-transport` exposes an explicitly paced send method and a strict receive
  method. The CLI bridge selects them only with the explicit flag or saved
  setting; default sessions keep their existing format.
- The S3 marker prevents a Shroud 2 parser from accepting this format. It does
  not add authenticated feature negotiation; both endpoints need matching
  operator configuration.
- Unit and loopback tests establish codec, adaptation-state, CLI validation,
  bridge framing, pacing, and authenticated QUIC code paths. The loopback test
  does not open a host TUN or establish two-host interoperability, full-session
  performance, traffic-analysis resistance, or release support.
- `scripts/validate_shroud3_tun_namespace.sh` exercises one UDP echo packet
  through two real TUN devices in separate nested network namespaces over a
  veth underlay, then checks process and control-plane cleanup. Its WSL2 result
  is local one-kernel evidence, not native two-host acceptance or a support
  claim.
