# SHPH Evidence Directory

This directory contains reproducibility artifacts, not source-of-truth code.

- `PHANTOM_SHROUD_AUDIT_2026-09-27.md` records local security fixes,
  validation gates, the 2026-09-27 owned-loopback probe run, synthetic
  blocking simulation, and a release microbenchmark. Its probe results do not
  include the separate 2026-09-28 campaign.
- `PHANTOM_SHROUD_AUDIT_2026-09-28.md` records the later dirty-tree validation,
  Criterion microbenchmarks, repeated loopback probes, and synthetic D4 smoke
  evaluation. None establishes roadmap validation.

- `GATE_EVIDENCE.md` is generated by `scripts/capture_evidence.sh` and records
  the exact tree, toolchain, platform, validation gates, and demo result.
- `VALIDATION_2026-09-04_V0.6.7-DEV.md` records the September 4 pre-commit
  validation run for `v0.6.7-dev` and its remaining host/tooling gates.
- `VALIDATION_2026-08-30_V0.6.6-DEV.2.md` records the previous publication
  tag validation and its remaining host gates.
- `CARGO_AUDIT.txt` records the latest RustSec scans for all four lockfiles,
  including their yanked-crate checks and tool/database versions.
- `QUINN_PROTO_0.11.19_SOURCE_VALIDATION_2026-10-12.md` records Windows and
  WSL2 engineering gates against the exact upstream `quinn-proto 0.11.19` tag
  source. It explicitly does not establish registry-backed locked or package
  validation.
- `LOCKED_VALIDATION_2026-10-13.md` records the checksum-verified official
  `quinn-proto 0.11.19` archive, locked local validation on clean source commit
  `aeb71d1`, and the remaining skipped host/service acceptance lanes. The full
  machine-specific collector output remains under ignored `benchmark-runs/`.
- `WINDOWS_NATIVE_VALIDATION_2026-08-25.md` is the current elevated Windows
  Wintun lifecycle, route/DNS rollback, and loopback WFP smoke record.
- `WINDOWS_WFP_CRASH_VALIDATION_2026-09-01.md` records the elevated,
  single-host forced-termination run: WFP policy persisted after a hard kill
  and was removed by explicit `shph down`. It does not prove automatic
  crash-time cleanup or packet-leak prevention.
- `WINDOWS_NATIVE_CLOSEOUT_2026-09-28.md` records a fresh elevated Windows
  native-TUN lifecycle and forced-termination/WFP cleanup run. It remains
  single-host evidence and does not close the required two-host campaign.
- `PACKAGE_VALIDATION_2026-09-02.md` records the sanitized Windows package
  manifest, checksum, allowlist, and publication-boundary checks. It is an
  engineering snapshot because the source tree was dirty and the local
  executable was unsigned.
- `CROSS_PLATFORM_NATIVE_TUN_VALIDATION_2026-08-25.md` records the separate
  Windows-Wintun to Linux-TUN direct-TCP IPv4 forwarding campaign, including
  external egress, throughput, reconnect, impairment, MTU boundary, session
  hold, and teardown.
- `OPTIONAL_XRAY_UNDERLAY_VALIDATION_2026-08-25.md` records the separate,
  bounded SOCKS5/Xray and Quick Tunnel interoperability checks. It does not
  promote the optional add-on into the direct release profile.
- `WINDOWS_NATIVE_VALIDATION_2026-08-09_POST_LOADER.md` is retained as a
  historical post-loader validation record.
- `docs/SECURITY_EVIDENCE.md` defines the evidence tiers and redaction review
  required before publishing any generated record.
- `docs/RELEASE_READINESS.md` defines the binding PASS/FAIL/SKIP semantics;
  a capability-gated `SKIP` is not a pass.
- Dated benchmark and public validation reports elsewhere under `docs/` are
  retained as historical or phase-specific evidence and identify their own
  platform and scope. Internal assessment material is maintained outside the
  publishable evidence bundle. None of these records is an independent audit.
- Machine-specific engineering snapshots under `benchmark-runs/` are ignored
  by Git and are not publication artifacts.

Regenerate the current gate record from the repository root:

```bash
./scripts/capture_evidence.sh
```

The script refuses dirty trees by default. Use `--allow-dirty` only for
intermediate engineering evidence, and keep the resulting `tree=dirty` label.

## Publication handling

Before publishing evidence to GitHub, review every file for private keys,
keystore material, peer addresses, hostnames, usernames, absolute paths, and
unredacted packet or command logs. The two-host validator stores its private
state outside the repository by default; publish only its generated,
sanitized Markdown reports and explicitly reviewed supporting data.
