# SHPH v0.6.4-dev.4 Benchmark and Validation Evidence

This report records the reproducible evidence collected for the
`v0.6.4-dev.4` developer release. It is deliberately scoped to local,
in-memory, synthetic, and code-path measurements. It is not Internet
throughput evidence, censorship-resistance evidence, or an independent
security audit.

## Shroud overhead measurements

These values are generated by the standalone benchmark harness using synthetic
payloads and the in-memory Shroud2 envelope path. They report extra wire bytes
relative to plaintext payload bytes; socket, IP, Ethernet, TUN, and Internet
costs are excluded.

| Profile or traffic model | Extra wire overhead |
| --- | ---: |
| Bulk | 24.965% |
| Video | 21.093% |
| Video, large near-MTU payloads | 1.427% |
| Video, balanced near-MTU payloads | 1.360% |
| Web | 90.340% |
| VoIP | 191.303% |
| SSH-sized interactive payloads | 422.775% |
| Tuned low | 179.399% |
| Tuned web | 64.575% |
| Tuned video | 18.446% |
| Tuned video, near-MTU payloads | 1.857% |
| Tuned bulk | 20.156% |
| Tuned VoIP | 126.978% |

The tuned profiles reduce selected overhead tradeoffs while retaining discrete
size classes and session-scoped randomized padding. They do not make all
traffic distributions equivalent, and the small-payload rows remain expensive
because padding has a fixed minimum cost.

## Criterion microbenchmarks

The Criterion harness completed 150 estimate files across cryptography,
defensive paths, handshakes, framing, Shroud2, identity records, and the
stateful tuned-padding paths. The command completed successfully. Criterion
comparison output includes ordinary performance-regression signals for some
microbenchmarks; those signals are reported for engineering follow-up and are
not correctness failures.

The benchmark additions cover:

- session-scoped padding state and reusable output buffers;
- tuned low, web, video, bulk, and VoIP profile selection;
- Shroud2 morphology and batch flush behavior;
- TCP/QUIC profile application paths; and
- tuned-profile frame and fuzz-input selection.

## Reproduction boundary

The full local campaigns used 100 latency iterations and 10,000 frames for both
`secure-default` and the explicit benchmark-only `classical-lab` profile.
`classical-lab` is not a production fallback and does not measure the secure
hybrid handshake.

The results do not establish:

- live two-host throughput or stable VPS uptime;
- native Linux TUN forwarding or full Windows Wintun packet-path acceptance;
- route, DNS, firewall, or killswitch behavior on every host;
- resistance to DPI, blocking, active probing, or traffic classification;
- DDoS capacity from single-process operation rates; or
- independent cryptographic or security-audit certification.

GitHub-hosted Linux and Windows jobs are separate reproducibility runs. Their
artifacts should be cited separately and must not be silently merged with this
workstation capture.
